# AMD SEV-SNP Attestation

**Focus**: Remote Attestation Mechanism  
**Research Phase**: 8  
**Status**: Technical Documentation

---

## Attestation overview

AMD SEV-SNP remote attestation lets a remote party verify that a VM runs expected code and configuration in genuine SEV-SNP hardware.

---

## Attestation Components

### 1. Attestation Report
- Generated by AMD Secure Processor (PSP)
- Contains measurements of guest state
- Signed by AMD attestation key
- Used for remote attestation

### 2. Guest Measurement
- Hash of guest firmware, kernel, and applications
- Represents the initial guest state
- Calculated during guest launch
- Used for verification

### 3. VCEK (Versioned Chip Endorsement Key)
- AMD-signed certificate for the specific CPU
- Used to verify attestation reports
- Includes CPU version and security information
- Part of the certificate chain

### 4. ARK (AMD Root Key)
- Root of AMD's certificate chain
- Used to verify VCEK certificates
- Hardcoded in verification software
- Foundation of trust

---

## Attestation Report Structure

```
AttestationReport {
  // Header
  version: Report version,
  guest_svn: Guest security version number,
  policy: SEV-SNP policy settings,
  
  // Family ID
  family_id: 16-byte family identifier,
  image_id: 16-byte image identifier,
  
  // Measurements
  measurement: SHA256(guest firmware, kernel, apps),
  launch_measurement: SHA256(launch measurements),
  
  // Host Data
  host_data: 32-byte host-provided data,
  
  // ID Info
  id_key_digest: Digest of ID key,
  author_key_digest: Digest of author key,
  
  // Report ID
  report_id: 96-byte unique identifier,
  
  // Signature
  signature: ECDSA signature over report data,
  signing_key: AMD attestation public key
}
```

## Certificate Chain

```
AMD Root Key (ARK)
    ↓
Versioned Chip Endorsement Key (VCEK)
    ↓
Attestation Key (ASK)
    ↓
Attestation Report Signature
```

### Certificate Details

#### ARK (AMD Root Key)
- Root of trust for AMD certificates
- Hardcoded in verification software
- Long-lived certificate
- Signed by AMD CA

#### VCEK (Versioned Chip Endorsement Key)
- Unique to each CPU model and stepping
- Includes CPU version information
- Signed by ARK
- Used to verify attestation keys

#### ASK (Attestation Signing Key)
- Used to sign attestation reports
- Embedded in the CPU
- Certificate chain to VCEK
- Provides per-CPU attestation capability

## Attestation Flow

### Step 1: Guest Launch
```
Guest Creation
    ↓
Load Guest Firmware
    ↓
Calculate Firmware Measurement
    ↓
Load Guest Kernel
    ↓
Calculate Kernel Measurement
    ↓
Start Guest Applications
    ↓
Calculate Application Measurements
    ↓
Final Measurement = Hash(all measurements)
```

### Step 2: Request Attestation
```
Guest invokes attestation request
    ↓
Request goes to AMD Secure Processor
    ↓
PSP generates attestation report
    ↓
Include guest measurements
    ↓
Sign with attestation key
    ↓
Return attestation report to guest
```

### Step 3: Certificate Retrieval
```
Guest retrieves VCEK certificate
    ↓
From AMD certificate service
    ↓
Or from local cache
    ↓
Verify certificate chain
    ↓
Extract attestation key
```

### Step 4: Remote Verification
```
Verifier receives attestation report
    ↓
Extract signature and data
    ↓
Verify certificate chain (ARK → VCEK → ASK)
    ↓
Verify signature with attestation key
    ↓
Extract measurements from report
    ↓
Compare with expected measurements
    ↓
Check security version number
    ↓
Check revocation status
    ↓
Make trust decision
```

---

## Measurement Details

### Launch Measurement
- Hash of initial guest state
- Includes firmware, bootloader, kernel
- Calculated during guest launch
- Immutable after launch

### Runtime Measurement
- Hash of runtime state
- Can include application state
- May change during execution
- Used for runtime attestation

### ID Key Digest
- Hash of the guest's identity key
- Used for guest identity verification
- Optional measurement
- Provides additional identity binding

## Attestation Policies

### Trust Levels
- **Full Trust**: All measurements match expected values
- **Partial Trust**: Some measurements match, others acceptable
- **No Trust**: Critical measurements don't match
- **Revoked**: Certificates or measurements are revoked

### Policy Configuration
```
AttestationPolicy {
  required_measurements: {
    launch_measurement: "expected_hash",
    id_key_digest: "expected_hash"
  },
  
  minimum_security_version: 1,
  
  allowed_policies: [
    "policy_value_1",
    "policy_value_2"
  ],
  
  revocation_check: true,
  
  certificate_validation: {
    require_ark_pinning: true,
    allowed_ark_hashes: ["ark_hash_1"]
  },
  
  trust_level: "full"
}
```

## Certificate Validation

### ARK Validation
- Compare with hardcoded ARK hash
- Verify certificate structure
- Check expiration
- Verify signature chain

### VCEK Validation
- Verify signed by ARK
- Check CPU version compatibility
- Verify certificate expiration
- Check revocation status

### ASK Validation
- Verify signed by VCEK
- Check attestation key validity
- Verify key usage
- Check for revocation

---

## Revocation Mechanisms

### Certificate Revocation
- Compromised certificates can be revoked
- Revocation lists published by AMD
- Verification software checks revocation
- Cached revocation information

### Measurement Revocation
- Compromised guest measurements can be revoked
- Revocation lists for specific measurements
- Time-based revocation for old measurements
- Platform-specific revocation

### Key Revocation
- Compromised attestation keys can be revoked
- CPU-level key revocation
- Platform key revocation
- Emergency revocation procedures

## Security Considerations

### Trusted Components
- AMD CPU hardware
- AMD Secure Processor firmware
- AMD certificate infrastructure
- AMD attestation keys

### Attack Vectors
- **Certificate Compromise**: If AMD certificates are compromised
- **Key Compromise**: If attestation keys are leaked
- **Measurement Replay**: Old measurements reused
- **Configuration Tampering**: Unauthorized configuration changes

### Mitigations
- Certificate pinning
- Short-lived certificates
- Regular measurement updates
- Multi-factor attestation
- Fallback verification methods

## Comparison with Intel TDX Attestation

| Aspect | AMD SEV-SNP | Intel TDX |
|--------|-------------|-----------|
| Attestation Source | AMD Secure Processor | TDX Module |
| Certificate Chain | ARK → VCEK → ASK | Intel Quote Service |
| Network Dependency | Optional (can cache certs) | Required (quote service) |
| Signature Type | ECDSA | ECDSA |
| Revocation Mechanism | Certificate revocation lists | Service-based revocation |
| Measurement Granularity | Launch + runtime | Boot + config + runtime |
