# AMD SEV-SNP Research

**Technology**: AMD Secure Encrypted Virtualization-Secure Nested Paging  
**Research Phase**: 8  
**Status**: Documentation in Progress

---

## Overview

AMD SEV-SNP (Secure Encrypted Virtualization-Secure Nested Paging) encrypts and integrity-protects virtual machine memory. Guest VMs are protected from the hypervisor and other software on the system.

---

## Key Concepts

### SEV-SNP (Secure Encrypted Virtualization-Secure Nested Paging)
- Memory encryption with integrity protection
- Secure nested paging for memory protection
- Attestation via attestation reports
- Guest state protection

### SEV (Secure Encrypted Virtualization)
- Base memory encryption technology
- Each VM has unique encryption key
- Hypervisor cannot access guest memory
- Foundation for SEV-SNP

### SNP (Secure Nested Paging)
- Adds integrity protection to SEV
- Prevents hypervisor memory tampering
- Reverse page table protection
- Guest page validation

---

## Security Properties

### Confidentiality
- Guest memory encrypted with AES-256
- Each VM has unique encryption key
- Keys managed by AMD Secure Processor
- Hypervisor cannot access guest memory

### Integrity
- Memory integrity protected via SNP
- Hypervisor tampering detected
- Reverse page table protection
- Guest page validation

### Attestation
- Remote attestation via attestation reports
- Measurement of guest state
- Cryptographic proof of correct execution
- Signed by AMD keys

## Memory Encryption

### Encryption Keys
- Each VM assigned unique encryption key
- Keys generated by AMD Secure Processor
- Keys never exposed to hypervisor
- Key destruction on VM termination

### Memory Protection
- All guest memory encrypted
- Encryption/decryption transparent to guest
- No performance impact for normal operations
- Keys managed in hardware

### Key Management
```
VM Creation
    ↓
PSP generates unique key
    ↓
Key loaded into memory encryption hardware
    ↓
VM can start encrypted execution
    ↓
VM termination
    ↓
Key securely destroyed
```

---

## Secure Nested Paging (SNP)

### Reverse Page Table Protection
- Hypervisor controls page tables
- SNP prevents malicious page table modifications
- Reverse page table adds integrity checks
- Guest can verify page table integrity

### Guest Page Validation
- Each memory page has validation flag
- Hypervisor cannot modify validated pages
- Guest controls which pages are validated
- Prevents hypervisor tampering

### Integrity Protection
```
Without SNP:
Hypervisor → Page Table → Physical Memory
(Vulnerable to tampering)

With SNP:
Hypervisor → Reverse Page Table → Physical Memory
                (Integrity protected)
```

## Attestation Mechanism

### Attestation Report
- Generated by AMD Secure Processor
- Contains measurements of guest state
- Signed by AMD attestation key
- Used for remote attestation

### Report Structure
```
AttestationReport {
  // Guest Measurements
  measurement: SHA256(guest firmware, kernel, apps),
  
  // Guest Info
  guest_svn: Security version number,
  policy: SEV-SNP policy settings,
  
  // Platform Info
  platform_info: Platform configuration,
  
  // Signature
  signature: ECDSA signature over report data,
  signing_key: AMD attestation public key
}
```

## Remote Attestation Flow

### Step 1: Guest Initialization
```
Guest Startup
    ↓
Load Firmware & Bootloader
    ↓
Calculate Boot Measurements
    ↓
Enable SEV-SNP
    ↓
Start Guest OS
    ↓
Ready for Attestation
```

### Step 2: Request Attestation
```
Guest invokes attestation request
    ↓
AMD Secure Processor generates report
    ↓
Include guest measurements
    ↓
Sign with AMD attestation key
    ↓
Return attestation report to guest
```

### Step 3: Remote Verification
```
Verifier receives attestation report
    ↓
Verify AMD signature
    ↓
Extract measurements from report
    ↓
Compare with expected measurements
    ↓
Check revocation status
    ↓
Make trust decision
```

## Security Considerations

### Trusted Components
- AMD CPU hardware
- AMD Secure Processor firmware
- AMD attestation keys
- Guest code and configuration

### Attack Vectors
- **Hardware Vulnerabilities**: CPU bugs, side channels
- **Firmware Compromise**: PSP vulnerabilities
- **Side Channels**: Timing, cache attacks
- **Denial of Service**: Hardware-level disruption

### Mitigations
- Regular security updates
- Defense in depth
- Monitoring and detection
- Redundancy and geographic distribution

## Performance Characteristics

### Expected Overhead
- **Memory Access**: Minimal overhead for encryption
- **Page Validation**: Additional cost for SNP validation
- **Attestation**: Local generation (no network dependency)
- **I/O**: Some operations require special handling

### Optimization Opportunities
- Batch proof generation within VM
- Cached attestation results
- Optimized memory access patterns
- Parallel computation within VM
