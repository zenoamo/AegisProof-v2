# Intel TDX Attestation

**Focus**: Remote Attestation Mechanism  
**Research Phase**: 8  
**Status**: Technical Documentation

---

## Attestation Overview

Intel TDX provides a remote attestation mechanism that allows a remote party to verify that a Trust Domain (TD) is running with the expected code and configuration in a genuine TDX environment.

---

## Attestation Components

### 1. TDREPORT (Local Attestation)
- Generated by TDX module for the TD
- Contains measurements of TD state
- Signed by TDX attestation key
- Used for local attestation within platform

### 2. Quote (Remote Attestation)
- Generated by Intel Quote Service
- Based on TDREPORT
- Signed by Intel's attestation key
- Used for remote attestation to external parties

### 3. Measurement Data
- Boot measurements (firmware, bootloader, kernel)
- Configuration measurements (TD configuration)
- Runtime measurements (application code)
- State measurements (runtime state)

---

## TDREPORT Structure

```
TDREPORT {
  // Header
  report_type: ATTESTATION_REPORT_TYPE
  report_id: 96-byte unique identifier
  
  // TD Measurements
  mr_tdowner: SHA256(TD owner configuration)
  mr_config: SHA256(TD configuration)
  mr_owner: SHA256(owner-defined data)
  mr_td: SHA256(TD runtime measurements)
  
  // TDX Module Info
  tdx_module_info: {
    version: TDX module version
    security_version: Security version number
  }
  
  // CPU Security Capabilities
  cpuid_security_features: CPU security capabilities
  
  // Signature
  signature: ECDSA signature over report data
  signing_key: TDX attestation public key
}
```

## Attestation Flow

### Step 1: TD Initialization
```
TD Startup
    ↓
Load Firmware & Bootloader
    ↓
Calculate Boot Measurements
    ↓
Load TD Configuration
    ↓
Calculate Config Measurements
    ↓
Start Guest OS
    ↓
Ready for Attestation
```

### Step 2: Generate TDREPORT
```
TD invokes TDG.VP.REPORT instruction
    ↓
TDX module generates report
    ↓
Include all measurements
    ↓
Sign with TDX attestation key
    ↓
Return TDREPORT to TD
```

### Step 3: Quote Generation
```
TD sends TDREPORT to Quote Service
    ↓
Quote Service validates TDREPORT
    ↓
Quote Service signs with Intel key
    ↓
Quote Service returns Quote
    ↓
TD has remote attestation capability
```

### Step 4: Remote Verification
```
Verifier receives Quote
    ↓
Verify Intel signature
    ↓
Extract measurements from Quote
    ↓
Compare with expected measurements
    ↓
Check revocation status
    ↓
Make trust decision
```

## Measurement Details

### mr_tdowner (TD Owner Measurement)
- Hash of TD owner's configuration
- Includes owner-defined policies
- Specific to TD owner identity
- Used to verify TD ownership

### mr_config (Configuration Measurement)
- Hash of TD configuration parameters
- Includes CPU features, memory layout
- Defines TD security properties
- Ensures consistent configuration

### mr_owner (Owner Data Measurement)
- Hash of owner-provided data
- Can include application measurements
- Customizable by TD owner
- Provides flexibility in attestation

### mr_td (TD Runtime Measurement)
- Hash of TD runtime state
- Includes loaded applications
- Reflects current execution state
- Used for runtime attestation

## Quote Service Architecture

### Intel Quote Service
```
┌─────────────────────────────────┐
│   Intel Quote Service            │
│  ┌───────────────────────────┐  │
│  │ Quote Generation          │  │
│  │ - Sign TDREPORT           │  │
│  │ - Add Intel signature     │  │
│  │ - Include revocation info │  │
│  └───────────────────────────┘  │
│  ┌───────────────────────────┐  │
│  │ Revocation Management      │  │
│  │ - Certificate revocation   │  │
│  │ - TDX module updates        │  │
│  │ - Security advisory info    │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

### Quote Service APIs
- **GetQuote**: Request quote for TDREPORT
- **VerifyQuote**: Verify quote authenticity
- **GetRevocationInfo**: Check revocation status
- **GetCertificateChain**: Get Intel certificate chain

## Verification Process

### Verification Steps
1. **Signature Verification**
   - Verify Intel's signature on Quote
   - Check certificate chain validity
   - Ensure certificate not revoked

2. **Measurement Extraction**
   - Extract TD measurements from Quote
   - Parse measurement structure
   - Verify measurement integrity

3. **Expected Comparison**
   - Compare with expected measurements
   - Check configuration matches requirements
   - Verify runtime measurements

4. **Security Version Check**
   - Verify TDX module security version
   - Check for known vulnerabilities
   - Ensure minimum security requirements

5. **Revocation Check**
   - Check if TD measurements are revoked
   - Verify TDX module not compromised
   - Check for security advisories

## Attestation Policies

### Trust Levels
- **Full Trust**: All measurements match expected values
- **Partial Trust**: Some measurements match, others acceptable
- **No Trust**: Critical measurements don't match
- **Revoked**: Measurements are explicitly revoked

### Policy Configuration
```
AttestationPolicy {
  required_measurements: {
    mr_tdowner: "expected_hash",
    mr_config: "expected_hash",
    mr_owner: "expected_hash",
    mr_td: "expected_hash"
  },
  
  minimum_security_version: 2,
  
  allowed_configurations: [
    "config_hash_1",
    "config_hash_2"
  ],
  
  revocation_check: true,
  
  trust_level: "full"
}
```

## Security Considerations

### Trusted Components
- Intel CPU hardware
- TDX module firmware
- Intel Quote Service
- Intel attestation keys

### Attack Vectors
- **Quote Service Compromise**: If Intel service is compromised
- **Key Compromise**: If Intel attestation keys are leaked
- **Measurement Replay**: Old measurements reused
- **Configuration Tampering**: Unauthorized configuration changes

### Mitigations
- Certificate pinning
- Short-lived certificates
- Regular measurement updates
- Multi-factor attestation
- Fallback verification methods
