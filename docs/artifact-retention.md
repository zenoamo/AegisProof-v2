# AegisProof Artifact Retention & Git Tracking Policy

Approved under Phase 3 (Git policy **C**: track sources + selected immutable
evidence artifacts; exclude large/regenerable binaries). This document is the
authoritative classification; `.gitignore` is its mechanical implementation.

### OBSOLETE — must NOT be committed

## 2. Retention rules
1. FROZEN artifacts are never modified, moved, or regenerated. Verification:
   `node scripts/verify_manifest.mjs` (every check PASS; includes the pinned
   Phase 4 production final hashes when the ceremony has been performed).
2. CANONICAL artifacts are hash-pinned; the cache manifest and every suite
   run re-verify them. A mismatch aborts the run (never treated as success).
3. EVIDENCE is append-only per mode: FAST and FULL write separate files (E-1).
   Re-running a mode replaces that mode's own record only, with a new
   timestamp; the replaced record's hashes remain checkable via Git history.
4. REGENERABLE artifacts must be reconstructible from CANONICAL/FROZEN inputs
   using only tracked scripts — this is what the CI pipeline exercises.

## 3. Hardhat interaction (incident 2026-08-04)
Hardhat 3's build system deletes unknown `*.json` directories under
`paths.artifacts` on every run (`cleanupArtifacts`). Evidence directories
under `artifacts/phase2/` were repeatedly wiped by `npx hardhat compile/run`.
Mitigation: hardhat build output is isolated at `artifacts/hardhat/`
(`paths.artifacts` in `hardhat.config.ts`). Never move phase2 JSON evidence
back under a directory hardhat manages.

## 4. Recovery procedures
- Evidence tree wiped: `node scripts/restore_phase2_inputs.mjs` then
  `node scripts/recover_phase2_cache.mjs` (rebuilds inputs, vkey, and cache
  manifest from intact canonical artifacts, asserting the pre-recorded hash
  chain), then re-run the suite (`--full`, then `--fast`).
- Dev setup missing: `node scripts/phase2_verify.mjs --setup` (DEVELOPMENT
  ONLY — production trusted setup remains Phase 4).
